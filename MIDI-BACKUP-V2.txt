TEST136 — Restore MIDI message types from backups

New MIDI backups include channel, CC/Note/Off type and number for all 71
assignments. Restoring shows the exact before/after changes before applying.
Type-only changes and disabled (Off) assignments are now restored too.
Older v1 backups retain their original channel/number-only behavior and
require matching types. Bank size, bank index and MIDI routing are excluded.

The restore preview warns about duplicate active assignments using the
proposed type, channel and number. Off assignments do not cause conflicts.
Changes are sent one at a time and checked against device readback. Failure
stops the batch; already-confirmed changes remain. Stop cancels unsent entries.

Use MIDI > Save MIDI backup / Restore MIDI backup. Launch: bash run.sh.
1,176 automated tests passed; Python compilation passed. Physical device and
GUI rendering verification were not available. Immersive functions remain deferred.


Format: af16rig-midi-assignments-backup-v2
Legacy format: af16rig-midi-channel-number-backup-v1
The 71 raw assignment words use the already verified native bit layout:
type bits14..15 (0CC,1Note,2Off), channel bits8..11, number bits0..7.
Type3, reserved bits12..13 and numbers above127 remain unsupported for changes.
Unknown unchanged values can still be archived without being rewritten.

No additional USB request or register is introduced. Restores use the existing
midi_remap worker command and its expected-raw-state / connection-generation
checks. The preview passes the requested type, and confirmation checks the
complete target word, including type. Legacy and batch callers remain supported.

New tests cover nine type transitions across all71 assignments, legacy
compatibility, type-only/Off previews, full-word confirmation, rejected
unsupported encodings and conflict detection. Existing partial failure, stop,
reconnect, file validation and restore tests remain passing.
