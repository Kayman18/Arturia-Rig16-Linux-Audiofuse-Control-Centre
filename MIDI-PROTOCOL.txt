TEST127 — Full eight-strip MIDI assignment template

MIDI now offers All controls (64) in the batch selector. Choose a MIDI channel
(1–16) and starting number (0–64), then Preview assignments. The template uses
eight consecutive numbers each for Fader, Pan, Mute, Solo, Aux 1, Aux 2, Aux 3
and Aux 4, in that order. For example, starting at 0 maps faders 0–7, pans 8–15,
mute 16–23, solo 24–31 and aux sends 32–63. Master and bank assignments remain
unchanged. Existing per-control eight-strip batches remain available.

Preview performs no device writes. The preview warns when proposed mappings
duplicate another supported stored channel/type/number assignment, including
master and bank-switch controls. Message-type meanings remain unverified;
this comparison does not claim all semantic MIDI conflicts are identifiable.
Stored type bits are kept unchanged; this does not activate an Off assignment.
Unsupported encodings block the entire template. Unchanged assignments are
omitted. Save MIDI backup before applying if you want to restore old mappings.

Apply uses the existing sequential guarded writer: fresh matching preflight,
one OUT per changed assignment, confirmation readback, and stop on first
failure. Stop/Close prevents remaining submissions; it cannot undo an already
sent write. Connection changes invalidate the preview. Normal polling stays
at its existing rate. No hardware change occurs automatically on startup.

Validation: 1051 automated tests passed and Python compilation passed. New

TEST115 — Backup and sequential restore
=======================================
No new USB requests or parameter addresses are introduced. Each changed
assignment is submitted through TEST114 midi_remap with the captured old
word and connection generation, and retains the existing message type.
The preview checks all 71 addresses before any submission. Each native write
still performs fresh matching readback preflight and send-once confirmation.
Only one remap is in flight, with a 120 ms UI scheduling yield between entries.
Stopping/closing prevents further submission; an already-queued write is not
withdrawn or undone. Connection loss uses existing pending-write discard.

Portable format: af16rig-midi-channel-number-backup-v1, device AF16Rig,
state_version 18, explicit boolean demo, and exactly 71 unique assignments.
Each entry contains parameter, index, raw uint16. Saved records require two
matching reads and stable=True. File load is bounded to 65,536 bytes, rejects
duplicate JSON keys, excessive nesting, bad types/addresses and missing entries.
A real-device restore rejects demo files. Changed raw values must satisfy
TEST114's supported encoding and match the current type bits. Target channel
and number are derived from the saved word; the expected old word is always
from current device capture, never taken from the file.

This is not a native preset file, a whole-device backup, a MIDI type editor,
or a MIDI routing backup. Hardware confirmation and persistence validation
remain pending. The tests exercise the existing remap path using Demo and
mock transport plus headless dialog lifecycle checks.

TEST114 — Guarded existing-assignment remapping
================================================
Extends TEST113 capture using the proven channel/number fields below.
Type bits 14/15 are retained; type code 3, reserved bits 12/13 and old number
codes above 127 are not written. The allowed target is:
    (old & 0xc000) | ((user_channel - 1) << 8) | user_number
Group 3 / parameter 20..34, at the indices registered by the agent.

Native global setter evidence: callback 0x1404cc280 -> 0x1404c0060 ->
0x1404c01c0; at 0x1404c034b it passes group 3, at 0x1404c0350 it supplies
the low 16-bit value, and 0x1404c0360 calls the common setter 0x14048faa0.
Together with the established scalar writer 0x1407c6eb0, this produces
vendor OUT 0x40, request 0x13, wValue parameter, wIndex element, length 2.
The callback packing code at 0x1404c33d7..0x1404c33e0 independently matches
the retained type/channel/number layout. Message-type enum labels remain
unverified; no new type-selection control or MIDI-routing control is added.

Arturia's manual documents MIDI channels 1..16 and Off / CC / Note selection:
https://dl.arturia.net/products/audiofuse-16rig/manual/audiofuse-16rig_Manual_2_0_2_EN.pdf
It does not establish the binary numeric enum mapping. MIDI channel codes
0..15 are displayed as 1..16; the raw zero-based code remains in exports.

Preflight requires two matching fresh reads of the exact old word. After a
single OUT, up to four two-read attempts confirm a stable target. Even an
uncertain OUT result is never resent; matching readback is the acceptance
criterion. This does not prove power-cycle persistence. Physical device
acceptance of these new writes is unverified in this environment.

Historical TEST113 implementation notes follow; their read-only limitation
applies to TEST113, before the guarded remapping above was added.

Agent registration loop 0x1404949be..0x140494c86 initializes EBX=0 and
increments to 8, supplying that index for parameter IDs 20..27 through
helper 0x1404a3e50. The following registrations 0x140494c8c..0x140494e2c
use index 0 for 28..34. Bank index 19 is bound at 0x140494e3e..0x140494e6a.
Channels-per-bank helper 0x1404a3f10 supplies parameter 18, index 0.
This yields 64 strip assignments + 7 singleton assignments + 2 bank values.

The existing recovered scalar read path 0x1407c6e70 uses vendor IN 0xc0,
request 0x90+group, wValue=parameter, wIndex=element, two-byte LE word.
For this page the only allowed request is 0x93 and the above 73 addresses.
Unsupported state versions are rejected before transfer. Short/error replies
stop the capture; -4 propagates device disconnection. No OUT path is added.

Assignment decoding evidence in callback 0x1404c2990:
0x1404c2da6 zero-extends the returned 16-bit value.
0x1404c2e94..0x1404c2e9b shifts 8 then masks 0xF for channel code.
0x1404c2e9f..0x1404c2ea3 shifts 14 then masks 3 for type code.
0x1404c2ea7..0x1404c2eae retains the low byte for number code.
0x1404c33d7..0x1404c33e0 recomposes type<<14 + channel<<8 + number.
Bits 12/13 are preserved as reserved_bits in the exported record. No semantic
label is assigned to those bits, type codes, or special/unassigned words.
Channel codes are shown as 0..15; no UI numbering conversion is assumed.

Each entry is read twice in one worker command. Matching reads are recorded
per entry, not presented as an atomic whole-device snapshot. The next entry
is submitted only after its predecessor's reply reaches the page, allowing
regular worker polling between entries. No intervals are changed. Page close,
refresh or connection-generation change invalidates the old request token.
Capture occurs on opening the MIDI page or explicit refresh, not continuously.
JSON reports retain raw words, both reads, decoded bit fields, errors, partial
completion and explicit demo labeling. Export freezes the report before the
file picker opens. Read/export is not a restorable configuration backup.

Remaining verification: native hardware read acceptance and physical mapping;
message-type enum labels; unused/unassigned encoding; MIDI port routing;
controller assignment editing, MIDI learn and configuration file restore.
No new MIDI writes are enabled, and no hardware confirmation is claimed.
