Implemented native requests
---------------------------
All use VID 1c75 / PID af21, wIndex zero, two-byte little-endian values.
Mute: group 0, parameter 7; read C0/90, write 40/10.
Mono: group 1, parameter 26 decimal; read C0/91, write 40/11.
Dim: group 1, parameter 27 decimal; read C0/91, write 40/11.
Speaker level: group 3, parameter 0; read C0/93, write 40/13.
C0/40 and request codes in these four lines are hexadecimal.

Writes require state version 18 and verified values. Each OUT is sent once.
Readback retries after 50/100/200/400 ms; matching actual state is required
for success, including when OUT returned an unusual status. Command errors
retain the handle for refresh. Physical removal or three consecutive polling
failures closes the connection. USB resets, kernel detachment and interface
claiming are not used.

TEST5 relative volume control
=============================
The user confirmed TEST4 works after the Mute-disconnect fix. TEST5 preserves
that recovery path and adds speaker-level increments using global group 3 /
parameter 0, signed 16-bit payloads and one OUT request 0x13 per click.

The current hardware value is read before each increment; the cached UI value
is not used as the write base. Only +/-1 raw steps inside the software subset
[-60, 0] are allowed. This range is an application restriction, not a recovered
native range or dB calibration. No automatic unmute or startup write occurs.

Additional volume investigation found an AFCC UI path at 0x140481a7b that
sign-extends a UI parameter and scales by 1/256, with -32768 as a sentinel.
Its exact correspondence to the AFSS global speaker-level field is unresolved;
it must not be used to label native raw reads as dB. In particular, a USB-audio
8.8 format and the UI-controller state field may use different representations.

Static analysis of the UI firmware's vendor dispatcher confirms that IN
requests 0x90..0x94 dispatch scalar reads by group. The callback writes the
returned value as a 16-bit word. None of this proves a particular acoustic
volume scale. The user must compare one TEST5 step with the front-panel display
before a calibrated dB slider is implemented.

TEST5 volume writes are unit-tested and exercised through the GUI in demo
mode. Physical-hardware volume validation is still pending.

TEST6 fixed-point volume correction
==================================

volume buttons do nothing. Their TEST5 report shows successful Mute/Dim/Mono
write/readback transactions, changing negative speaker-level values, and no
volume-write attempts. The last raw signed level is -435.

values. The user still needs to compare TEST6's dB display and step behavior
with the hardware. No claim of a physically tested TEST6 volume write is made.

TEST9 packed readback correction — supersedes TEST7/8 scalar input assumptions
=============================================================================
TEST7 report: channel 5 phase/HPF reads zero; OUT returns 2, four verification
reads remain zero. TEST8 report: selecting channel 1 yields phase=16 and
HPF=65535. Selecting channel 2 yields phase=0 and HPF=65535. The phase=16
packed word after channel-5 writes is direct evidence for the bit representation.

Firmware static evidence (UI firmware 2.0.1):
  0x08095b98 forwards a scalar vendor read to the state getter and stores one
  16-bit result. Its parameter/element getters address packed words.
  0x0809d4a0 handles an individual bit update: index >> 4 selects a word,
  index & 0xf selects the bit, BIC/ORR changes it and 0x0809dd48 stores the word.
  0x0809dd88 independently implements the same indexed bit operation.
  0x0809d794..0x0809d808 iterates the bits of packed fields for state changes.
These functions corroborate distinct packed-word and per-bit operations.

Correct rear switch read:
  bmRequestType C0, bRequest 91, wValue 19 (phase) or 97 (HPF),
  wIndex 0, length 2. wValue IDs here are decimal; request bytes are hexadecimal.
  selected_bool = (packed_word >> (ui_channel - 1)) & 1
For channels 1–16 there is only packed word zero.

Per-channel switch write remains:
  bmRequestType 40, bRequest 11, same wValue ID,
  wIndex = ui_channel - 1, little-endian payload 0000/0100.
Readback verification must return to packed word zero and extract the bit;
it must not reuse the write's bit index as the read's word index.

TEST9 does not construct or write full bitmasks. It preserves the per-channel
OUT command supported by the reports, fixes verification, accepts every complete
16-bit mask (including ffff) and records packed values in snapshots. It does
not infer or restore the user's previous settings after earlier unconfirmed
commands. Physical validation of the corrected readback is pending TEST9.

TEST11 rear stereo linking
==========================

AFCC registration at 0x1404925d7..0x14049269a:
  EBX starts at zero and advances by two up to 16; EDI advances by one.
  InputLinkBack_<EDI> is bound twice to ID 24, using EBX and EBX+1.
  Both registrations use helper 0x1404a27d0. This establishes odd/even pairing
  and that both channel flags are associated with one pair-level UI property.

UI firmware descriptor tables at 0x080d6fbc and 0x080d7854 classify persistent
ID 24 as type 3 with one storage word, matching the packed switch format.
Type getter 0x0809d47c reads these two-byte descriptors. Literal references to
0x080d6fbc occur at 0x080957f8 and 0x08095b1c; the duplicate table is referenced
at 0x080d75b8. Metadata is exported in recovered-wire-types.json.

Read link mask: bm C0, request 91, wValue 24 decimal, wIndex 0, length 2.
For selected UI channel c, first bit = 2*floor((c-1)/2), second bit = first+1.
Equal zero flags -> unlinked; equal one -> linked; unequal -> Mixed.
Write each channel flag using bm 40, request 11, wValue 24, bit index in wIndex,
with 0000 or 0100 payload. Request bytes are hex, parameter ID is decimal.

Each flag is reread before deciding whether an OUT is necessary. Individual
readback and final pair readback are required. Other pair flags are never
written. If firmware propagates the first change to its partner, the second
OUT is skipped. Partial failure retains diagnostics and does not trigger an
automatic rollback or repeated write. Native linked-setting synchronization is
left to the firmware; the application does not copy gain itself.

Physical stereo-link behavior remains pending the user's TEST11 test.
